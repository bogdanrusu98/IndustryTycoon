# Exhaustive production asset usage audit

Audit date: 2026-10-11. Branch: `feature/core-prototype`. Baseline: `e29422b06d75f58a95f11f680ad95bc0af5910e9`. This is a fresh recursive census and Play Mode audit, not a restatement of M19 coverage.

## Accounting

- **107 external files: 21 FBX exports + 86 PNG textures**; no standalone material files or other model formats exist in the source tree.
- **20 byte-unique meshes; 18 selected production assets, all integrated.** Three unused exports: two alternative rock models and one byte-identical nested crate export. Zero unsuitable or unexplained model exports.
- **21 embedded material records and 78 embedded texture/video payloads** were separately decoded and inspected. 26 embedded images are pixel-identical to external images; the other 52 are alternate encodings of the same atlases (maximum 128px mean absolute RGB error <0.60/255). No additional asset identity was hidden inside an FBX.
- **Six newly attached instances:** two initial saw-station shells, two matching blades, one Iron Vein ore model, one dynamic stored-ore model. These reuse appropriate canonical meshes and materials.
- **36 normal-camera runtime probes** cover all 18 selected sources, each split wheel/blade, reused building/resource roles and all six escarpments.

## Texture and material accounting

Every external image has an individual path/hash/decode result and production match or unused-map reason in [files.tsv](Documentation/AssetUsageAudit/Sources/files.tsv). All 86 were inspected in three contact sheets: [0](Documentation/AssetUsageAudit/Sources/textures-0.jpg), [1](Documentation/AssetUsageAudit/Sources/textures-1.jpg), [2](Documentation/AssetUsageAudit/Sources/textures-2.jpg). Thirty canonical external textures are imported in production (18 base colors and 12 normals); the duplicated crate atlas matches the same production image.

All 78 embedded images have their FBX origin, byte hash, decoded pixel hash, dimensions, closest external atlas, comparison error and explicit unused reason in [embedded-textures.json](Documentation/AssetUsageAudit/Sources/embedded-textures.json). Individually inspected sheets: [0](Documentation/AssetUsageAudit/Sources/embedded-0.jpg), [1](Documentation/AssetUsageAudit/Sources/embedded-1.jpg), [2](Documentation/AssetUsageAudit/Sources/embedded-2.jpg). These alternate encodings are intentionally replaced by explicit external production texture references.

The [binary FBX node inventory](Documentation/AssetUsageAudit/Sources/fbx-material-texture-nodes.json) accounts for all 21 material objects and 78 Texture/Video objects, including filenames, properties and embedded payload hashes. The [production material audit](Documentation/AssetUsageAudit/production-materials.txt) lists every actual shader and texture binding. Metallic/roughness/emission and packed source maps remain explained auxiliary maps: the mobile presentation uses opaque Lit base color/normal with controlled uniform roughness, avoiding reflective/noisy tiny silhouettes. Packed yellow/pink data maps are not diffuse textures. No invalid or missing material is accepted.

## Reproduction and implementation

`ExhaustiveProductionIntegration.Apply` is called by the deterministic scene builder after world composition. It owns only visual attachments, renderer suppression and art transforms. `ExhaustiveAssetUsageAudit.InspectSources`, `FinalizeStaticAudit` and `Run` provide the independent source/static/runtime audits. Three regression tests protect cutter/ore mappings and courier forward/outward-wheel/rear-cargo alignment. Python source/embedded-image inspection tools are under `Tools/AssetUsageAudit`.

Technical basis: [Unity axis conversion](https://docs.unity3d.com/ScriptReference/ModelImporter-bakeAxisConversion.html), [world renderer bounds](https://docs.unity3d.com/ScriptReference/Renderer-bounds.html), [camera projection](https://docs.unity3d.com/ScriptReference/Camera.WorldToViewportPoint.html). Community cross-check: [imported FBX rotation discussion](https://discussions.unity.com/t/imported-objects-always-rotated/801061). The implementation preserves imported correction below an art-only parent; runtime visibility is measured rather than inferred from prefab presence.
